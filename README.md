# 애플 KR 리퍼 감시기

apple.com/kr 리퍼비쉬 스토어(Mac · iPad · AirPods · Apple TV · 액세서리)를 **5분마다** 확인해서
**신규 등록 / 재입고 / 가격 인하**가 생기면 폰으로 푸시를 보낸다. **푸시를 탭하면 그 제품 주문 페이지가 바로 열린다.**

GitHub Actions에서 돌아서 맥이 꺼져 있어도 동작한다. 현재 재고표는 [STATUS.md](STATUS.md).

## 알림에 붙는 두 축

| 축 | 계산 | 비고 |
|---|---|---|
| **스펙점수** (0–100) | 칩 성능 45 (세대 반영) · 메모리 30 · 저장공간 15 · 출시연도 10 | iPad는 메모리 대신 등급(Pro > Air > mini > 기본) |
| **할인율** | 같은 구성 신품(F→M 부품번호)의 현재 애플스토어 가격 대비 | 신품이 없으면(단종·CTO) 표시 안 함 |

2026-09-25 실측: 현행 신품이 있는 Mac은 할인율이 **14.5–15.1%로 거의 고정**이다.
그래서 실제로 싼 걸 잡는 신호는 할인율 수치보다 **💸 가격인하 알림**과 **17%+ 이상치**(당시 iPad mini 19.1%, iPad A16 17.1%)다.

푸시 우선순위: 스펙 75+ 또는 할인 20%+ → 긴급(5), 스펙 55+ 또는 할인 17%+ → 높음(4), 나머지 → 보통(3).

## 폰 설정 (1회)

1. App Store에서 **ntfy** 설치
2. `+` → 토픽 이름에 저장소 Secret `NTFY_TOPIC`과 같은 값 입력 → Subscribe
3. Actions 탭 → **알림 테스트** → Run workflow → 폰에 뜨면 성공

토픽 이름은 비밀번호처럼 다룬다. 이름만 알면 누구나 구독할 수 있다 (재고 알림이라 유출돼도 피해는 없음).

## 동작 규칙

- **재입고**: 연속 2회(약 10분) 목록에서 안 보이면 품절로 기록, 다시 뜨면 재입고 알림. 10분 안에 빠졌다 돌아온 건 안 잡힌다.
- 조회나 파싱에 실패한 카테고리는 그 회차 상태를 건드리지 않는다 (가짜 품절/재입고 방지).
- 한 번에 15건 넘게 뜨면 점수 높은 순 15건만 개별 푸시, 나머지는 요약 1건.
- 신품 가격은 3일마다 갱신한다.
- 커밋은 재고가 바뀐 회차에만 생긴다.

## 로컬 실행

```bash
DRY_RUN=1 python3 watch.py
```

`DRY_RUN=1`이면 푸시 대신 payload를 출력한다. 표준 라이브러리만 쓴다.

## 크림(KREAM) 아이패드 프로 감시 — `kream.py`

크림의 "Apple Refurbished"는 **애플 인증 리퍼가 아니라 판매자 등급 중고**다 (애플 1년 보증·AppleCare+ 가입 보장 없음).

- 조건: 검색어 `리퍼비시 아이패드 프로`, 등급 **S+ / S / A**, 판매가 **≤ 999,000원**, 판매중
- 이 조건에 새로 들어오는 순간만 푸시: 🆕 신규 등록 / 🔁 품절→재입고 / 💸 가격이 선 아래로
- 탭하면 `kream.co.kr/products/{id}` → 크림 앱이 깔려 있으면 앱으로 열림
- 우선순위: M2 이상 긴급 · M1 높음 · A12X/Z 보통 · 그보다 구형(2015–2017) 무음
- 크림은 TLS 지문으로 봇을 막아서 `curl_cffi`(Chrome 위장)로만 조회된다. 크림 단계가 실패해도 애플 감시는 계속 돈다.
- 조건 바꾸려면 `kream.py` 위쪽 `KEYWORD` / `MAX_PRICE` / `GRADES`.
